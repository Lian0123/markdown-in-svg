本文書の位置付け（Status of This Memo）

本文書は新しい Markdown-in-SVG 交換形式を提案するものであり、既存規格の転載ではない。構成は IEEE 技術標準の概要、引用規格、定義、要求事項および附属書を参考とする。要求水準には RFC 2119 と RFC 8174 を用い、セキュリティ、IANA、相互運用性に関する規定も設ける。

本文書は複数の編集方針を組み合わせた独立草案である。IEEE の編集審査を通過したとは主張せず、RFC、提出済み Internet-Draft、IEEE P シリーズ草案のいずれでもない。 MISVG-SPEC-0001 はプロジェクト内の識別子であり、標準化団体が付与した番号ではない。正式提出時には、提出先の手続、テンプレート、言語、権利表示および編集要件に合わせる必要がある。本文書は利用者に代わって公開ライセンスを選択しない。外部公開前に権利者が決定する。

要約（Abstract）

MISVG は、編集可能な Markdown 原文、原文とビューの対応、および静的 SVG ビューを単一の UTF-8 XML 文書に格納する。Markdown を内容の唯一の正本とし、SVG をその視覚表現とする。一般的な SVG ビューアで表示でき、MISVG 対応ツールは抽出、検証、編集および再生成を行える。本仕様はコンテナ、文字処理、原文ダイジェスト、版管理、静的描画サブセット、対応情報、エラー処理および適合要件を定義する。ダイジェストの一致が示すのは原文との対応の検査結果に限られ、ビューの意味的な正しさや文書の信頼性を証明しない。

1. 概要

1.1 適用範囲（Scope）

本仕様は単一の .svg ファイル内における Markdown 原文の保存、原文と SVG ビューの対応、基本的な編集手順、およびファイルとツールの適合性を定義する。説明カード、フローチャート、構成図、短い仕様書および視覚的な知識文書を対象とする。

本改訂は static 描画プロファイルだけを定義する。HTML 描画プロファイル、汎用的な Markdown と SVG の双方向変換、完全な組版エンジン、共同編集の転送プロトコル、電子署名、PDF の改ページ、図の意味を表すオントロジー、アクセシビリティ認証は定義しない。

1.2 目的（Purpose）

実装は、スクリプト実行や依存資源のダウンロードなしに Markdown を抽出できなければならない（MUST）。Producer は単独で表示可能な静的 SVG を出力し、検索・抽出可能なテキストを保持しなければならない（MUST）。文書は内容の原文、描画結果、対応データを明確に区別しなければならない（MUST）。

1.3 適用上の限界

すべての SVG アプリケーションによる metadata の保持や、異なるフォント／描画エンジン間での画素一致は保証しない。画像だけを見る AI は MISVG 原文にアクセスできない。原文処理を行う AI またはツールに対して、システムは XML または抽出済みテキストを提供しなければならない（MUST）。

3. 用語、定義および要求水準

3.1 要求を表す用語

大文字の MUST、MUST NOT、SHALL、SHALL NOT、SHOULD、SHOULD NOT、MAY は [BCP14a] と [BCP14b] に従って解釈する。すべて大文字である場合だけ規定の意味を持つ。本文書は必須要求に主として MUST を用いる。日本語の表現に添えた大文字の語が要求水準を示す。

用語 意味
MUST / SHALL 適合するために必須。
MUST NOT / SHALL NOT 適合するために禁止。
SHOULD / SHOULD NOT 推奨／非推奨。逸脱する場合は結果を理解し理由を記録する。
MAY 許容される選択肢。

3.2 定義

用語 定義
原文（source） m:source を解析して得られる Markdown 文字列。
ビュー（view） ルート直下にあり m:presentation/@root-ref が参照する唯一の SVG g 部分木。
原文ダイジェスト 8.1 の原文バイト列に対する SHA-256 値。
対応（binding） 原文の行範囲からビュー要素 ID への写像。双方向の可逆性を意味しない。
文書 ID 同一文書の改訂を通じて保持される UUIDv4 URN。
改訂番号（revision） 同一文書で確定した内容または描画の変更に対する増加整数。
プロファイル コンテナ内の描画能力に課す共通の制約。
未知の拡張 ツールが完全には解釈できない外部名前空間の metadata。

3.3 処理の役割

Reader は内容を抽出して報告する。Producer は有効なパッケージを作成する。Editor は既存パッケージを変更する。Validator は宣言した範囲の検査を実行する。一般的な SVG Viewer は図形を表示するだけでは MISVG Reader に該当しない。

4. アーキテクチャおよび原文の優先性

4.1 論理モデル

文書は原文、描画記述、ビューをそれぞれちょうど一つ含まなければならない（MUST）。Markdown は内容の正本、対応データは索引、SVG は内容の視覚表現である。

SVG コンテナ
├── title + desc              人および支援ツール用の概要
├── metadata
│   └── m:document
│       ├── m:source          唯一の内容原文
│       ├── m:presentation    原文ダイジェスト、生成器、ビュー参照
│       ├── m:bindings?       原文の行 → ビュー ID
│       └── m:extensions?     意味を変えない任意の metadata
└── g                         静的な図形とテキストのビュー

4.2 内容の忠実性

Producer は原文が表す可視内容と関係を保持しなければならず（MUST）、原文にない実質的な記述をビューに追加してはならない（MUST NOT）。装飾、背景、改訂情報、文書識別子は表示してもよい（MAY）が、内容と区別できなければならない（MUST）。Markdown 構文記号やリンク参照定義を逐語表示する必要はない。

フローチャートでは矢印の方向、条件、意味が原文の明示的な記述から導けなければならない（MUST）。位置や色だけから関係を推測することはこの要求を満たさない。0.1 は汎用の機械可読な関係グラフを提供しない。ノード／辺の照会が必要なシステムは、独立に版管理する拡張仕様を定めることが望ましい（SHOULD）。

4.3 不一致時の処理

原文とビューが不一致の場合、Reader は原文が正本であることを報告し、ビューが信頼できないと警告しなければならない（MUST）。Editor は原文から再生成するか、ビューの変更を明示的に原文に反映してから再生成しなければならない（MUST）。OCR や幾何学的推論で原文を自動上書きしてはならない（MUST NOT）。

5. XML コンテナおよびフィールド

5.1 直列化および名前空間

コンテナは [XML] と [XMLNS] に適合する UTF-8 XML 1.0 文書でなければならない（MUST）。Producer は UTF-8 BOM を出力してはならず（MUST NOT）、Reader はファイル先頭の UTF-8 BOM を受け入れなければならない（MUST）。XML 宣言がある場合、version は 1.0 でなければならず（MUST）、encoding が指定される場合は大文字小文字を問わず UTF-8 でなければならない（MUST）。

ルートは {http://www.w3.org/2000/svg}svg でなければならない（MUST）。MISVG 0.1 の名前空間は次に固定する。

https://example.org/ns/markdown-in-svg/0.1

これは草案試験用の識別子であり、登録済みの接続先でもプロジェクトが管理するサービス URL でもない。ツールは完全な名前空間 URI とローカル名で要素を比較しなければならず（MUST）、例の m 接頭辞に依存してはならず（MUST NOT）、名前空間の解決のためにネットワーク要求を行ってはならない（MUST NOT）。

ルートは title、desc、metadata、g をこの順に各一つだけ含み、他の子要素を含んではならない（MUST）。ルートは version="1.1"、width、height、viewBox を持たなければならない（MUST）。寸法と他の属性は箇条 7 に従う。title と desc は文書を説明する空でないプレーンテキストでなければならない（MUST）。これは最低限の説明要件であり、アクセシビリティ認証ではない。

m:source 内を除き要素間の字下げ空白を含めてもよい（MAY）。要素だけを持つコンテナに他の非空白テキストを置いてはならない（MUST NOT）。原文の外にはコメントを置いてもよい（MAY）が、規定の意味はない。XML 宣言を除く処理命令、DOCTYPE、独自実体宣言を含めてはならない（MUST NOT）。

5.2 文書 metadata

svg:metadata は一つの m:document だけを含まなければならない（MUST）。m:document は m:source、m:presentation、任意の m:bindings、任意の m:extensions をこの順で各最大一つ含まなければならない（MUST）。MISVG 要素の属性は、明示された xml:space を除き名前空間を持たない。

m:document 属性 要求 定義
version MUST 0.1 に固定。仕様草案の改訂とは別。
profile MUST static に固定。
doc-id MUST 小文字の urn:uuid: に [UUID] 準拠の UUIDv4 が続く。附属書 A。
revision MUST 1–9007199254740991 の十進整数。先行ゼロなし。

5.3 原文要素

m:source 属性 要求 定義
media-type MUST [MDTYPE] の text/markdown に固定。
dialect MUST commonmark-0.31.2 に固定。MISVG のトークンであり IANA variant 登録ではない。
xml:space MUST preserve に固定。

m:source はテキストおよび／または CDATA のみを含み、子要素、コメント、処理命令を含んではならない（MUST）。内容は空でもよい（MAY）。xml:space は XML の改行正規化を無効にしない。

5.4 描画記述

m:presentation は次の属性を持つ空要素でなければならない（MUST）。

属性 定義
root-ref ビュー g の ID。# のない ID。
source-digest sha256: と 64 文字の小文字十六進数。
renderer 空でない生成器名。Unicode コードポイント 1–128 個。
renderer-version 空でない生成器の版。Unicode コードポイント 1–64 個。SemVer は必須でない。

生成器の識別は診断用であり、信頼できる出所の証明として扱ってはならない（MUST NOT）。同じ名前と版でも画素一致は保証しない。root-ref はルート直下の唯一の g を参照しなければならない（MUST）。

5.5 閉じたコア語彙

コア MISVG 要素は未定義の属性や子要素を含んではならない（MUST NOT）。未知のコア語彙は無効としなければならず（MUST）、無視して本版の検証を通過させることはできない。外部拡張は箇条 10 に従い m:extensions のみに置く。

6. Markdown および文字処理

6.1 正規化された原文

取り込み時、Producer は CRLF と単独 CR を LF に正規化しなければならない（MUST）。この変換以外では、末尾空白、tab、空行、最終 LF の有無、Unicode の合成形を含むすべての原文文字を保持しなければならない（MUST）。自動 trim、末尾改行の追加、NFC／NFD の適用を行ってはならない（MUST NOT）。

Reader は XML 解析後の文字列を用いなければならない（MUST）。[XML] は物理的な改行を先に正規化するが、&#13; で導入された U+000D はその処理では消えない。解析後の原文に U+000D がある場合、Reader は適合を拒否して E_SOURCE を報告しなければならず（MUST）、黙って修復して元ファイルを有効と主張してはならない。

U+0000 など XML 1.0 で禁止された文字は取り込み失敗としなければならず（MUST）、Producer は黙って削除してはならない（MUST NOT）。ファイル先頭の BOM は原文に含めない。原文内の U+FEFF は通常のデータであり保持しなければならない（MUST）。

6.2 Markdown の意味

原文は [CM] に従って解析しなければならない（MUST）。GFM 表、取り消し線、タスクリスト、YAML front matter、数式、Mermaid 実行、include 命令は本版の拡張構文ではない。0.1 コア描画を主張するツールは、意味を変える方言を黙って用いてはならない（MUST NOT）。

CommonMark の raw HTML ノードは元のマークアップを可視テキストとして表示しなければならず（MUST）、活動 HTML として実行してはならない（MUST NOT）。コードブロックはテキストとして扱い（MUST）、実行してはならない（MUST NOT）。通常のリンクはラベルを表示し、その直後に解決済みリンク先を可視テキストとして表示しなければならない（MUST）。既にリンク先を表示している自動リンクは重複不要とする。画像は代替テキストとリンク先を可視表示しなければならず（MUST）、代替テキストが空の場合は固定文字列 [image] を用いる。これらは静的出力規則であり、解析は引き続き CommonMark に従う。

リンク先は文書内ではデータにすぎない。Producer／Reader は解析や描画に伴って自動アクセスしてはならない（MUST NOT）。相対パスは元の値のまま保持して表示しなければならず（MUST）、文書パスや xml:base を基準に自動解決しない。

6.3 XML エスケープと往復

Producer は XML テキストのエスケープまたは CDATA を用いてもよい（MAY）。どちらも抽出後に同じ原文を得られなければならない（MUST）。原文に ]]> がある場合、CDATA を用いる Producer は、例えば ]]]]><![CDATA[> のように区間を分割するか、通常の XML エスケープを用いなければならない（MUST）。ハッシュは XML 復号後に計算し（MUST）、CDATA タグや &amp; の字面を対象にしない。

無損失抽出が意味するのは正規化された原文文字列の保持であり、元の .md の BOM、CRLF バイト、XML 接頭辞、属性順序の復元は保証しない。

7. 静的描画プロファイル

7.1 許可する要素

次の制限は [SVG11] の閉じたサブセットを定義する。許可されていない要素、属性、名前空間をビュー内に含めてはならない（MUST NOT）。

位置／要素 子要素
ルート svg 5.1 の四つの子要素のみ。
ビュー g と入れ子の g g、text、rect、circle、ellipse、line、polyline、polygon、path。
text、tspan テキストおよび tspan。
幾何図形 子要素なし。

foreignObject、script、style、image、a、use、defs、フィルタ、アニメーション、外部フォントは本プロファイルの対象外とする。Producer は文書内容を担う文字を path に置換してはならない（MUST NOT）。純粋な装飾や矢印には path を用いてもよい（MAY）。

7.2 許可する属性

属性は名前空間を持たず、名前空間宣言は属性として数えない。ルート svg 以外のすべてのビュー要素は id を持ってもよい（MAY）。ルートでは version、width、height、viewBox のみを許可する。

要素 id 以外の許可属性
g transform および下記の共通描画属性。
text、tspan x、y、dx、dy および共通描画属性。text はさらに transform、xml:space="preserve" を許可。
rect x、y、width、height、rx、ry、transform および共通描画属性。
circle cx、cy、r、transform および共通描画属性。
ellipse cx、cy、rx、ry、transform および共通描画属性。
line x1、y1、x2、y2、transform および共通描画属性。
polyline、polygon points、transform および共通描画属性。
path d、transform および共通描画属性。

共通描画属性は fill、stroke、stroke-width、stroke-linecap、stroke-linejoin、font-family、font-size、font-weight、font-style、text-anchor に限る。他の CSS の入口はない。

fill と stroke は none または #RRGGBB のみを許可し、十六進数の大小文字は問わない。font-family は空でない名前のコンマ区切りリストとし、各名前は Unicode の文字、十進数字、ASCII 空白、ハイフンだけを含み、引用符、括弧、エスケープを含まない。最後は sans-serif、serif、monospace のいずれかでなければならない（MUST）。他の列挙値は [SVG11] に従う。font-weight は normal、bold または 100–900 の 100 刻み整数、font-style は normal、italic、oblique に限る。

7.3 幾何形状とキャンバス

ルートの width、height は単位なし、先行ゼロなしの 1–16384 の十進整数でなければならず（MUST）、積は 16777216 を超えてはならない（MUST NOT）。viewBox は数値として 0 0 width height の四値を表さなければならない（MUST）。その他の長さは有限で単位なしの SVG 数値でなければならず（MUST）、font-size は正（MUST）、stroke-width、寸法、半径は非負（MUST）とする。本版では text／tspan の x、y、dx、dy は単一数値だけを許可する。百分率、単位、CSS 変数、calc()、非有限値は許可しない。

d、points、transform の構文は [SVG11] に従い、すべての数値は有限でなければならない（MUST）。path は空でない有効な d を持ち（MUST）、polyline／polygon は有効な points を持たなければならない（MUST）。既定値、描画順序、描画属性の継承は [SVG11] に従う。

Producer は可視文字をキャンバス内に配置し、切れ、文字同士の重なり、判読困難な前景／背景色を避けなければならない（MUST）。原文言語を表示できるフォントが不足する場合、描画上の制限を報告しなければならず（MUST）、欠字の四角を成功と見なしてはならない。正確なフォント寸法や画素位置は実装間の適合要件ではない。

7.4 テキストと読み順

ビューの XML 順序は妥当な読み順に従うことが望ましい（SHOULD）。内容文字は text／tspan を用いなければならない（MUST）。Producer は見出し、段落、リスト、引用、強調、コードに適切な改行と書式を用いることが望ましく（SHOULD）、初期配置をスクリプトに依存してはならない。原文全文の保持だけではスクリーンリーダーや WCAG の要件を満たさない。

8. ダイジェスト、同期および編集トランザクション

8.1 ダイジェスト算法

source-digest は次の手順で生成しなければならない（MUST）。

  1. 安全な XML パーサーで m:source のテキスト／CDATA 文字をすべて取得し、文書順に連結する。
  2. 箇条 6 を確認する。空白削除や LF 追加をしない。
  3. BOM なし UTF-8 に符号化する。
  4. [SHA256] に従って SHA-256 を計算し、64 文字の小文字十六進数にする。
  5. ASCII 文字列 sha256: を前置する。
source_digest = "sha256:" + lower_hex(SHA256(UTF8(source)))

対象は原文だけであり、文書 ID、revision、renderer、対応、拡張、SVG は含まない。循環ダイジェストや XML 正規化は不要である。配置だけの変更では値は変わらない。

8.2 対応状態

Reader は計算値と宣言値を比較しなければならない（MUST）。不一致は E_DIGEST_MISMATCH としなければならない（MUST）。未検証の復旧モードで原文を抽出してもよい（MAY）が、パッケージを有効と主張してはならない（MUST NOT）。

一致時に報告できるのは source-binding=matched だけである。これを署名有効、著者認証済み、ビュー検証済み、安全で信頼可能と呼んではならない（MUST NOT）。一致していても、ビューだけが変更されたり、攻撃者が原文とダイジェストを同時変更したりする可能性がある。

8.3 原子的な更新

Editor は一回の変更確定時に次を実施しなければならない（MUST）。

  1. 元ファイル全バイトの SHA-256 をローカル前提条件として記録する。このトランザクション指紋は形式内に保存しない。
  2. 利用者の意図に従って原文および／または配置を変更し、必要に応じてビューと対応を再生成する。
  3. doc-id を保持し revision を 1 増加する。上限では確定を拒否する。
  4. source-digest を更新し候補を検証する。古いビューを隠すためにダイジェストだけを更新してはならない。
  5. 書き込み前に、ロックまたはストレージ側の比較交換機構のもとで前提条件を再確認する。
  6. 中間状態を公開しない原子的置換／トランザクションで確定する。失敗時は元ファイルを保持する。

前提条件が成立する場合だけ上書きできる。不成立なら E_CONFLICT を報告しなければならない（MUST）。ロックなしの確認後書き込みでは本節を満たさない。同じ revision は同じファイルを意味せず、競合判定を revision だけで行ってはならない（MUST NOT）。

原文、描画、対応、metadata のいずれも変えない XML の再直列化では revision を維持してもよい（MAY）。新規文書は revision 1 で開始しなければならない（MUST）。独立文書として複製する場合は [UUID] に従って新しい UUIDv4 を生成しなければならず（MUST）、例の UUID を再利用できない。移動やバックアップは独立文書の新規作成ではない。

8.4 マージと復旧

実装は原文を単位に三方向マージし、その後ビューを再生成することが望ましい（SHOULD）。Git の XML テキストマージ成功を意味的マージの成功と見なしてはならない（MUST NOT）。未解決の競合マーカーを含む候補を編集完了として確定してはならない（MUST NOT）。マーカーが元から説明内容である場合、明示的な文脈に基づいて保持してもよい（MAY）。

原文が失われるか抽出不能なら、残るのは通常の SVG であり、有効な MISVG と主張してはならない（MUST NOT）。修復は区別できる新たな結果を生成しなければならず（MUST）、入力を黙って変更してはならない（MUST NOT）。

9. 原文との対応（Source Bindings）

m:bindings は省略してもよい（MAY）。存在する場合は一つ以上の空の m:bind を含まなければならない（MUST）。各 bind は target、start-line、end-line を持ち、他の属性を持ってはならない（MUST）。

target はビュー内の既存要素の裸の ID でなければならず（MUST）、対応集合内で同じ target を複数回用いてはならない（MUST）。ビューの ID はすべて一意で附属書 A の文法に従い（MUST）、ビューのルート g は ID を持たなければならない（MUST）。複数の target が同一の原文範囲を指してもよい（MAY）。

行番号は 1 起算で両端を含む。LF で分割し、末尾が LF なら最後の終端用空断片を除く。空原文は 0 行とする。"a\n" は 1 行、"a\n\n" は 2 行、"\n" は 1 行である。1 ≤ start-line ≤ end-line ≤ 行数 を満たさなければならない（MUST）。

空原文に対応を含めてはならない（MUST）。すべての行を覆う必要はなく、対応は完全な描画の証明ではない。原文変更後、Editor は影響範囲の対応を再計算するか全対応を削除しなければならず（MUST）、古いと分かっている行番号を保持してはならない（MUST NOT）。視覚要素の意味が不変なら ID を安定させることが望ましい（SHOULD）。

10. 拡張、バージョンおよび保持

10.1 バージョンの判定

Reader は version、名前空間、profile を明示比較しなければならない（MUST）。0.1 だけを実装する Reader が 0.2、1.0、別の名前空間、非 static profile を受け取った場合は E_UNSUPPORTED を報告しなければならず（MUST）、互換性を推測しない。未検証の復旧モードでデータを読めるが、対応範囲を明示しなければならない（MUST）。

0.x 間の互換性は保証しない。仕様改訂 0.1.1 はワイヤ形式を変えない編集改訂でもよい（MAY）。必須フィールドの追加、ダイジェストや内容の意味の変更は新しいワイヤバージョンと名前空間を用いなければならない（MUST）。

10.2 任意の拡張

m:extensions は一つ以上の外部名前空間要素を含んでもよい（MAY）。最上位拡張の名前空間は空であってはならず（MUST）、SVG、MISVG、XML のいずれでもあってはならない（MUST NOT）。拡張部分木全体に SVG／MISVG 要素を含めてはならない（MUST NOT）。テキストと属性は不活性なデータであり、コード実行を要求できない。

拡張には無視可能な補足 metadata だけを格納する。コア原文の優先性、解釈、セキュリティ要求、ビュー生成の意味を変更してはならない（MUST NOT）。無視すると誤解が生じる機能は新しい profile／version として別に定義し、この任意拡張機構に入れてはならない。

Reader は未知の拡張を無視してもよい（MAY）が、コア原文の解釈を保たなければならない（MUST）。内容を変えない往復では、Editor は未知拡張の要素／属性の展開名、文字列値、子ノード順序、テキストを保持しなければならない（MUST）。接頭辞、属性順序、CDATA 境界は保持不要である。

変更後も未知拡張が有効か判定できない Editor は、通常保存を中止し E_EXTENSION_EDIT を報告するか、明示的な「未知拡張の削除」操作により別の結果を保存しなければならない（MUST）。未知の古いダイジェストや行番号を保持して同期済みと主張できない。削除は利用者または呼び出し元の明示選択がある場合だけ許可する。

11. 適合性および相互運用性

11.1 文書の適合性

MISVG 0.1 static を主張する文書は、箇条 4–10 と附属書 A の適用される MUST／MUST NOT をすべて満たさなければならない（MUST）。XML Schema の成功は構造上の証拠の一つにすぎず、原文ダイジェスト、参照、SVG サブセット、意味、視覚の検査を代替しない。

11.2 役割ごとの適合性

役割 必要な能力
Reader 安全な解析、コア構造と版の認識、無損失抽出、ダイジェスト検査、エラー／制限の報告。未検査のビューを検証済みと呼べない。
Producer 適合コンテナと static profile、内容／文字の保持、ダイジェストと生成器情報、忠実性と視覚の検査。
Editor Reader／Producer 要件に加え、原子的更新、競合、revision、対応、未知拡張処理。
Validator 検査範囲の明示、11.3 の報告。部分検査を全面適合と表現しない。

11.3 検査の観点

Validator は次を個別報告しなければならない（MUST）。

  • structure：XML、metadata、フィールド、一意性、参照。
  • source-binding：原文規則、ダイジェスト、行範囲。
  • static-profile：全要素、属性、値域、基礎 SVG 文法。
  • content-fidelity：原文とビューが同じ実質的内容を保つか。
  • visual-review：描画された文字、読み順、切れ、重なり、欠字。

各状態は pass、fail、not-checked、unsupported のいずれかでなければならない（MUST）。未実行項目は not-checked としなければならず（MUST）、pass としてはならない。ダイジェスト成功は他の成功を意味しない。全面適合の主張には五項目すべての成功証拠が必要であり（MUST）、最後の二項目には人による審査を含めてもよい（MAY）。

11.4 相互運用性の検証

役割適合を主張する実装は附属書 B の適用試験を実行して結果を記録しなければならない（MUST）。Producer／Editor のリリース試験は二つの独立 SVG 描画器とツール間の抽出・再格納を含むことが望ましい（SHOULD）。本プロジェクトの例だけの成功は一般的な相互運用性認証ではない。

11.5 資源制限

実装はファイルサイズ、原文サイズ、XML 深さ、ノード数、文字列長、図形複雑度、処理時間に公開可能な制限を設けなければならない（MUST）。初期運用ではファイル 8 MiB、原文 1 MiB、深さ 64、ノード 50000、単一 path 65536 文字を推奨する（SHOULD）。これは実装上の推奨で、形式の合法性上限ではない。制限による停止は E_LIMIT／unsupported としなければならず（MUST）、入力の不正を断定できない。

12. エラー処理

コード 意味／最低限の処理
E_XML XML 不正、非対応の符号化、禁止された宣言。通常解析を停止。
E_STRUCTURE 必須フィールド、順序、個数、型、コア語彙の不正。
E_UNSUPPORTED 非対応の版、名前空間、方言、profile。推測しない。
E_SOURCE 原文の文字／ノード規則違反。
E_DIGEST_MISMATCH 計算ダイジェストと宣言値の不一致。
E_REFERENCE 重複 ID、不正な root-ref／target／行範囲。
E_PROFILE 静的要素、属性、値の制約違反。
E_CONTENT ビューによる実質的内容の欠落、変更、追加。
E_VISUAL 観測された切れ、重なり、欠字、判読不能。
E_CONFLICT 元ファイルが変更された。上書きしない。
E_EXTENSION_EDIT 未知拡張の安全な更新／保持ができない。

複数エラーがある場合は最初または全部を報告してもよい（MAY）が、診断を増やすために危険な内容を実行してはならない（MUST NOT）。診断には要素パス、フィールド、原文行を添えることが望ましい（SHOULD）。既定で原文全文、秘密、完全なローカルパスを外部サービスに送ってはならない（MUST NOT）。

13. セキュリティおよびプライバシー上の考慮事項

13.1 XML と活動内容

すべての処理器は外部実体、DTD 読み込み、ネットワーク schema 解決、XInclude 展開を無効化しなければならない（MUST）。信頼できない入力は DOM、ブラウザーなどの実行環境に渡す前に検査しなければならず（MUST）、活動 SVG を表示してから無害化してはならない。CDATA は文字列容器であって無害化機構ではない。

静的許可リストはイベント属性、スクリプト、CSS url()、外部資源、外部 HTML を除外する。原文中の HTML、JavaScript、リンク、命令もデータとしてのみ扱わなければならない（MUST）。ツールは資源消費を制限し、エラー時には関係する処理を停止しなければならない（MUST）。

13.2 AI の信頼境界

Markdown、コメント、拡張、生成器名は信頼できない文書データである。「システム指示」、ツール呼び出し、アップロード要求、権限宣言を名乗っていても受信側は権限を引き上げてはならない（MUST NOT）。文書を AI に送るアプリケーションは利用者の許可と文書内容を区別しなければならない（MUST）。原文に基づくコード実行、ネットワーク要求、ファイル操作は MISVG 解析に含まれない。

13.3 プライバシーと隠れた内容

画面にない内容も原文や metadata に残り得る。公開ツールは原文全文と metadata の確認機能を提供しなければならず（MUST）、視覚マスクをデータ削除と見なしてはならない（MUST NOT）。機密情報の削除は原文、ビュー、対応、拡張をすべて対象としなければならない（MUST）。新しい公開派生文書には新しい doc-id を与えることが望ましい（SHOULD）。

13.4 完全性と真正性

鍵のない SHA-256 ダイジェストは著者を認証できず、内容とダイジェストの同時改ざんも防げない。本版は電子署名、信頼ルート、時刻証明、失効機構を定義しない。source-digest がこれらを保証すると主張してはならない（MUST NOT）。

14. IANA および識別子に関する考慮事項

本草案は新しい IANA 登録を要求しない。外側のメディアタイプは [SVG11] の image/svg+xml でなければならない（MUST）。内包原文には [MDTYPE] の text/markdown を用い、新メディアタイプや登録済み Markdown variant を導入しない。

識別しやすい .misvg.svg を推奨する（SHOULD）が、通常の .svg も有効である。ファイル名は名前空間と構造の検査を代替しない。未登録の application/misvg を本仕様の正式メディアタイプとして示してはならない（MUST NOT）。

名前空間は 5.1 の草案識別子である。正式公開前に維持者は長期管理できる名前空間を選び、移行を定義しなければならない（MUST）。URI の変更で既存ファイルが自動更新されることはない。無許可で IEEE、IETF、W3C の識別子を本仕様の正式登録表示に用いることはできない。

15. バージョン管理方針および変更管理

公開者は仕様草案改訂、ワイヤ形式バージョン、個別文書 revision を別々に記録しなければならない（MUST）。正誤表は対象箇条と相互運用性への影響を示さなければならない（MUST）。ワイヤ上の意味を変える改訂は新しいワイヤバージョンを用いなければならない（MUST）。

0.x から安定版 1.0 に進む前に、維持者は名前空間管理とライセンスの確定、二つ以上の独立 Reader／Producer 間の交換試験、文字と競合の試験、脅威モデル審査、正式な互換性方針を完了することが望ましい（SHOULD）。将来の html profile、図の関係モデル、資源格納、スタイル資源、署名は個別提案とし（SHOULD）、版管理なしで static を変更しない。

附属書 A（規定）：字句および構造上の制約

次の正規表現は文字列全体に一致しなければならない（MUST）。別記しない文字範囲は ASCII とする。

ID        = [A-Za-z][A-Za-z0-9._-]{0,63}
DIGEST    = sha256:[0-9a-f]{64}
POSINT    = [1-9][0-9]*
UUID4URN  = urn:uuid:[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}

POSINT には各フィールドの値域も適用する。要素の個数は次のとおり。

svg := title, desc, metadata, g
metadata := m:document
m:document := m:source, m:presentation, m:bindings?, m:extensions?
m:source := XML character data / CDATA only
m:presentation := empty
m:bindings := m:bind+
m:bind := empty
m:extensions := foreign-element+

schema/misvg-metadata-0.1.xsd は metadata 部分木の補助 schema であり、SVG 全体を対象としない。すべての字句詳細、ダイジェスト、参照、SVG 値域、資源安全性、視覚要件を網羅しない。XSD 成功だけでは適合を主張できない。

附属書 B（規定）：適合性試験要件

実装は役割に該当する試験を網羅しなければならない（MUST）。「有効」は他条件も満たす前提とする。試料変更後は、不一致自体を試す場合以外は正しいダイジェストを再計算しなければならず（MUST）、別原因で目的の不良を隠さない。

T07 abc に LF を追加 異なるダイジェスト。trim しない。 R/P/E/V
T08 XML 原文内の物理 CRLF と LF XML 復号後に等価、同一ダイジェスト。 R/E/V
T09 原文に &#13; E_SOURCE。 R/E/V
T10 é と e＋U+0301 異なるバイト列を保持し、異なるダイジェスト。 R/P/E/V
T11 原文変更、旧ダイジェスト保持 E_DIGEST_MISMATCH。同期済みとしない。 R/E/V
T12 ビュー文字だけ変更 ダイジェストは一致し得る。忠実性は fail。ダイジェスト専用ツールは忠実性未検査と報告。 P/E/V
T13 二つ目の source／document、未知のコア属性 E_STRUCTURE。 R/E/V
T14 重複 ID、不正 root-ref／target、行範囲超過 E_REFERENCE。 R/E/V
T15 source 内の子要素／コメント E_SOURCE または E_STRUCTURE。 R/E/V
T16 DOCTYPE／外部実体／処理命令 拒否。外部ネットワーク／ファイル読み込みなし。 R/E/V
T17 script、イベント属性、foreignObject、style、href、data URI、URL paint E_PROFILE。事前実行／読み込みなし。 P/E/V
T18 未知の版／profile／方言 E_UNSUPPORTED。互換性を仮定しない。 R/E/V
T19 Reader が未知の不活性拡張を受信 無視可能。コア解釈は不変。実行なし。 R/V
T20 未知拡張を持つ原文の編集 E_EXTENSION_EDIT、または明示的削除後に別保存。 E
T21 読み取り後に他処理が変更。同じ revision でも E_CONFLICT。元ファイル保持。 E
T22 確定中断／書き込み失敗の模擬 元ファイル完全。途中結果を公開しない。 E
T23 内容文字を path 化、切れ、欠字 profile／visual-review または content-fidelity が失敗。 P/E/V
T24 公開した制限を超過 E_LIMIT／unsupported。必ずしも invalid ではない。 R/P/E/V
T25 metadata を除去し SVG のみ残す 通常 SVG になり得るが MISVG ではない。 R/E/V
T26 原文に画像、raw HTML、コード、相対リンク 6.2 の静的表示。自動要求／実行なし。 P/E
T27 空原文、末尾 LF、連続 LF の行数 箇条 9。存在しない行を対応させない。 R/P/E/V
T28 ファイル BOM と原文 U+FEFF 前者を受容。後者を保持してハッシュ対象にする。 R/E/V
T29 内容不変の XML 再直列化 原文、ダイジェスト、拡張の意味を保持。revision 維持可能。 E
T30 寸法上限超過、非有限値、不正 path／transform static-profile が失敗。 P/E/V

R/P/E/V は Reader、Producer、Editor、Validator を表す。Validator は宣言範囲のみが対象だが、未実行項目を報告しなければならない（MUST）。

# 注文フロー

1. 顧客が支払いを完了する。
2. 倉庫が支払い成功を確認してから出荷を手配する。

規則：支払いが成功していない場合は出荷しない。

通常手順：安全な読み取り → 原文抽出 → 対応検査 → Markdown 編集 → ビュー生成 → 行対応とダイジェスト更新 → 内容・描画検査 → 原子的確定。配置だけの変更でも revision は増加し、原文不変ならダイジェストは不変。

ダイジェストの最小 Python 例：

import hashlib

def source_digest(parsed_source: str) -> str:
    if "\r" in parsed_source:
        raise ValueError("E_SOURCE")
    return "sha256:" + hashlib.sha256(
        parsed_source.encode("utf-8")
    ).hexdigest()

この関数は安全な XML 解析やビュー検証を担当しない。例のビューは原文に基づく手動配置であり、本パッケージは汎用 Markdown 組版エンジンを提供しない。

附属書 D（参考）：設計理由およびトレードオフ

決定 理由と代償
Markdown を唯一の内容正本にする 原文の競合を避ける。ドラッグや文字変更には明示的な書き戻し手順が必要。
SVG metadata を使う 非表示の原文を同一ファイルに保持。描画／最適化ツールが削除する可能性がある。
ネイティブの static SVG サブセット 外部依存と活動内容を減らす。HTML 表、画像、完全な CSS は直接使えない。
CommonMark の版を固定 方言の変化を防ぐ。GFM／Mermaid は別の拡張か版が必要。
原文だけをハッシュ 単純で再現可能、自己参照なし。ビュー完全性や署名は保証しない。
任意の行対応 実装・診断しやすい。AST の同一性や任意の双方向編集は意味しない。
コア語彙を閉じる 誤記や版違いを検出。新機能には版管理が必要。
画素一致を主張しない フォント、環境、描画器で変わるため、視覚検査が別途必要。

初版は交換仕様を意図的に小さく保つ。長文や複雑な表には Markdown／HTML と SVG 挿図の組合せが引き続き適する場合がある。本形式は一枚の図に編集可能な原文を保持する用途を対象とする。

附属書 E（参考）：編集上の根拠および参考文献

  • RFC 7322, RFC Style Guide：要約、位置付け、箇条参照、引用分類、セキュリティ構成を参考とする。全書式規則を実装するものではない。
  • IEEE SA Standards Style Manual, 2021：概要／引用／定義の順序、検証可能な要求、規定／参考附属書の分離。
  • IEEE SA — Drafting the Standard：正式 IEEE 草案は同手続とテンプレートに従う。本草案は未実施。
  • RFC 2606, Reserved Top Level DNS Names：例示用ドメイン。example.org は正式な名前空間管理が未確立であることを示す。
  • SVG 1.1 Metadata：SVG は他 XML 名前空間の metadata を許容し、MISVG 固有モデルは本草案が新規定義する。
